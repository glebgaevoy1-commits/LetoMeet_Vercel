# LETOMEET update — 20 November 2026

Based on `LETOMEET-main (3).zip`. Backend, QR generation, admin tools and existing data models are preserved.

## What changed

- Light/dark toggle in the header. Defaults to light mode and saves your choice in this browser when storage is available.
- Homepage banner carousel: up to six upcoming published or recurring events, ranked by registration count. Swipe, use arrow buttons, or focus the strip and use keyboard arrows. No automatic movement.
- Responsive header, event pages, forms, sharing buttons and admin controls; collapsible catalog filters on phones; reduced-motion support.
- Separate display coordinates for 83 named rooms, placed inside the room near/above its printed label. Includes B19. Original navigator `x`/`y` coordinates are preserved. `marker_x`/`marker_y` are used consistently on event previews, catalog mini-maps and the main map.
- Sharing on every saved event page, including the page immediately after creation: Telegram/WhatsApp/Discord/Instagram logos, Telegram, WhatsApp, copy invitation for Discord/Instagram, copy link, and the device's native share menu where supported. Existing QR downloads remain available for published events.
- A creation-form note explains sharing and moderation. Unpublished events clearly warn that their links cannot be opened by other users until approval.

## Install into your existing project

1. Back up your project. Extract the **changes-only ZIP** into the repository folder that contains `main.py`, preserving the `static/` and `templates/` folders. Replace the matching files. The full ZIP is an alternative clean source copy.
2. Keep your existing environment variables, database, `instance/`, uploaded photos and hosting configuration. This update needs **no database migration, new dependencies, API keys, or SMTP changes**.
3. Commit and push the changed files to the branch used by your host, then deploy. For a local Python server, restart it. Reload the page; use Ctrl+Shift+R if old assets remain cached.
4. Open the homepage, toggle the moon/sun, and open an event. Sharing controls are below its map. After creating an event, the same controls appear on its saved page.

The full source ZIP intentionally omits `.git`, real environment files, databases, uploads, caches and editor settings. It does not replace your live accounts or events. Your original ZIP is unchanged.

## Sharing behavior and limitations

- Telegram and WhatsApp open a prepared invitation. The user chooses a destination and confirms sending. Nothing is posted automatically.
- Discord and Instagram buttons copy an invitation for pasting into the app. The native menu may also offer those apps, depending on the OS, installed apps and supported content. This is not automatic posting to a server, feed or Story.
- Native sharing and automatic clipboard access depend on browser support and normally require HTTPS (localhost is suitable for testing). If copying is denied, the page selects the text for manual copying.
- Links use the domain currently open. Share from the production domain, not a localhost or preview deployment. Existing hash-based routes do not provide unique social preview images/titles per event.
- MR, MH3 and Li remain at their existing coordinates: the supplied plans do not identify a single unambiguous matching room label. Hallway/navigation points are unchanged. Corrected display points are visual estimates from the provided plans, not a surveyed routing map.
- The carousel's popularity measure is registrations, not views or social shares. Empty data shows an invitation to create an event.
